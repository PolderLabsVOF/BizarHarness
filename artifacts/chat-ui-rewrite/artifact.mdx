## What we're building

A **from-scratch rewrite** of the chat UI tab in `bizar-dash`. Inspired by the Gemini Advanced "Hello, [name]." first-run screen. Calm, dark, minimal. Every element earns its place. The composer is always one click away. Side panels slide in and out — they never vanish. The greeting and suggestion cards set the tone on first visit.

## Why a complete rewrite

Three prior iterations left the chat in a brittle state:

1. **Structural refactor** — split 728-line `Chat.tsx` into 11+ components. Good bones, but no design vision.
2. **Gemini-inspired pass** — added gradient greeting, suggestion cards, pill composer. Fixed critical bugs (dead CSS, missing classes, `window.confirm`).
3. **Polish pass** — narrowed panels, fixed composer centering, derived theme gradients from `--accent`, added responsive breakpoints.

The polish pass improved things but **band-aided inconsistencies** rather than designing a coherent whole. The composer was a single row that fought the toolbar. The agent `<select>` was replaced with a popover but the popover positioning was inconsistent. The topbar, sessions header, and info card titles all used different visual languages. The mobile breakpoint at `1024.98px` was a workaround.

The user asked for a clean rewrite. **This plan delivers one.**

</RichText>

## Design system

### Color tokens (use existing from `main.css:100-220`)

```
--bg              page background        (#0e0e10)
--bg-1            card surface           (#18181b)
--bg-2            hover / active         (#27272a)
--border          hairline               (rgba(255,255,255,0.08))
--border-strong   hover border           (rgba(255,255,255,0.16))
--text            primary text           (#ececf1)
--text-muted      secondary text         (#8e8ea0)
--accent          theme accent           (#8b5cf6 — purple)
--success / --warning / --error / --info   (oklch semantic)
--gradient-hello  light-accent → accent  (THEME-AWARE)
--gradient-name   accent → warm          (THEME-AWARE)
```

**Gradient rule:** `color-mix(in oklab, var(--accent), ...)` so the hello text follows the theme. Change `--accent` → both gradients update automatically.

### Typography

- **UI text:** Inter (existing)
- **Code/model IDs:** JetBrains Mono (existing)
- **Greeting:** clamp(2.25rem, 5vw, 3.5rem), weight 700, line-height 1.1
- **Subtitle:** clamp(1.125rem, 2vw, 1.5rem), weight 500, muted
- **Message body:** 0.9375rem / line-height 1.6
- **Eyebrow labels** (panel headers): 0.6875rem uppercase, weight 600, letter-spacing 0.08em, muted

### Motion

```
--motion-fast   120ms   hover, focus
--motion-base   200ms   state changes
--motion-slow   320ms   panel slide, sheet overlay
--motion-ease   cubic-bezier(0.2, 0, 0, 1)
```

Reduced-motion: `prefers-reduced-motion: reduce` zeros all transitions globally.

### Radius scale

```
--radius-sm    6px     small chips, attachment tags
--radius-md   10px     cards, buttons, agent chip
--radius-lg   14px     message bubbles, composer pill
--radius-pill 999px   pills, badges
```

<Callout id="callout-risks" tone="warn">

### Risks

- **Use-chat hook signature drift:** If `useChat.ts` doesn't expose a method the new components need (e.g. `setPinned`, `setCreating`), the rewrite stalls. Mitigation: read `useChat.ts` before writing any component, document any gaps.
- **App.tsx imports:** `App.tsx` imports `Chat` from `./views/Chat`. If the new `Chat` signature changes, App.tsx breaks. Mitigation: keep the same `Props` interface.
- **CSS specificity wars:** New components using new classes might collide with existing classes that use the same names (e.g. `chat-suggestions`). Mitigation: scope-check before overwriting; prefer long specific names.
- **MobileChat hooks mismatch:** MobileChat.tsx must use the same `useChat` hook. Mitigation: MobileChat uses the same shared components, just a different layout.

</Callout>
