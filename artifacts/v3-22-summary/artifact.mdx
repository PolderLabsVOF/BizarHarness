## 1. Chat UI rewrite (Gemini-inspired)

Complete from-scratch rewrite of `bizar-dash/src/web/views/Chat.tsx` (728 lines → 250 lines). 12 new components in `bizar-dash/src/web/components/chat/`.

**Layout:** 3-column responsive grid (sessions 200/240px | thread | info 240/260px). On tablet (768-1023px) sessions becomes an overlay sheet; on mobile (under 768px) both panels are overlay sheets.

**First-run welcome screen:** centered "Hello, [project]." with gradient text that derives from `--accent` via `color-mix(in oklab, ...)` — change `--accent` and both gradients update automatically. 4 suggestion cards in an auto-fit grid (4-up at ≥1100px, 2-up at 600-1099px, 1-up under 600px).

**Floating pill composer:** sticky at bottom-center of the thread, max-width `min(880px, 100%)` so it fits any viewport. Column layout (textarea on top, toolbar below). Custom `AgentChip` popover replaces the broken native `<select>` — keyboard-accessible, theme-controlled, no positioning surprises.

**Mobile-safe:** composer pill uses `max-width: min(880px, 100%)` so it never overflows on a 414px viewport. Session and info panels slide in via `transform: translateX` (never `display: none`).

**Fixed bugs:** dead CSS override at `main.css:8217`, 3 missing CSS classes (`chat-sessions-new`, `-empty`, `-count`), `window.confirm()` replaced with `useModal()`, race condition in `onCreateSession`, `onRegenerate` no longer loads wrong session when `sessionId` is empty.

</RichText>

<RichText id="agent-knowledge">

## 2. Agent knowledge protocol (Obsidian)

**New global rule #12** in `config/agents/_shared/AGENT_BASELINE.md`:

> **Project knowledge lives in `.obsidian/`. Read it before you start, write to it when you learn.**

Every Bizar agent now reads the vault at session start, before non-trivial decisions, and when context feels stale. Odin is responsible for always updating the vault after significant work, regardless of who did the work.

The vault structure: `.obsidian/index/` (high-level), `.obsidian/bugs/` (postmortems), `.obsidian/agents/<name>/` (per-agent memory), `.obsidian/workflows/` (procedures), `.obsidian/daily/` (running log).

</RichText>

<RichText id="skills">

## 3. Three new skills installed at `~/.opencode/skills/`

**`obsidian`** — when to read the vault (session start, before decisions, after user corrections) and when to write (after completing work, on discoveries, on patterns). The O in Odin stands for "oblige the system": Odin always updates the vault.

**`glyph`** — visual plan/recap artifacts in `artifacts/<slug>/artifact.mdx`. Documents the full MDX block vocabulary (RichText, Callout, Checklist, Table, CodeTabs, Decision, OpenQuestions, FileTree, Stat, Workflow, Mockup, Diagram) and the common pitfalls (FileTree `change` must be one of `added|modified|removed|renamed`; MDX heading `<N` breaks the validator).

**`read-the-damn-docs`** — BuilderIO's principle, Bizar-flavored: when using a library/tool/API you don't fully understand, READ THE DOCS before guessing. Hierarchy of truth: official docs > source code > examples > StackOverflow > your prior model. Always use the `webfetch` tool for library APIs you haven't touched in this session.

</RichText>

<RichText id="heads-up">

## 6. Pre-push heads-up system

**New file `.bizar/PRE_PUSH_NOTES.md`** created by `bizar init`. Agents append dated entries with severity (blocker | warning | info), area (cli | dash | plugin | npm | docs | build), description, and mitigation.

**New CLI subcommand `bizar heads-up`** with subcommands:
- `bizar heads-up list` — print active entries
- `bizar heads-up check` — exit 0 (clear) or 1 (blockers exist)
- `bizar heads-up archive` — move active entries to the Resolved section

**`bizar update`** now gates on heads-ups: blockers refuse the update (require `--force`), warnings prompt for confirmation, clear state proceeds.

</RichText>

<RichText id="sessions-visibility">

## 7. Sessions visibility

**New endpoint `GET /api/opencode-sessions`** reads `~/.local/share/opencode/opencode.db` via `better-sqlite3`. Returns the 200 most-recently-updated non-archived opencode sessions.

**`SessionList` has a "Bizar / All" toggle** (Bizar-only by default). When "All" is selected, opencode sessions are merged into the list sorted by `mtime`. Clicking an opencode session opens it in the opencode web UI (`/opencode/session/<id>`) in a new tab.

</RichText>

<RichText id="installer-updater">

## 8. Installer + updater overhaul

**`install.sh`** now verifies 14 tools (node, uv, uvx, bun, jq, sqlite3, gh, opencode, python3, make, g++, plus originals) and installs native build deps via apt (`build-essential`, `python3`, `libsqlite3-dev`). The skills loop installs the 3 new skills from `config/skills/` if not already present.

**`cli/update.mjs`** now: pull → heads-up check → install skills → rebuild dashboard → run test gate → restart dashboard. Each step is gated on the previous one succeeding.

</RichText>

<Callout id="callout-learnings" tone="success">

## Key learnings from this release

1. **Theme-aware gradients beat hardcoded colors.** Using `color-mix(in oklab, var(--accent), ...)` for the greeting text means the design follows the user's chosen theme. Change `--accent` from purple to blue and everything updates automatically.

2. **Native `<select>` is uncontrollable.** Browsers render it as a modal-style dropdown that breaks the composer layout. For 100 lines of code, a custom button + popover with `useState` + outside-click handler gives full theme control and reliable positioning.

3. **The task tool is reliable for tiny prompts, fragile for complex ones.** A "pong" sanity check works; a 200-line dispatch prompt returns empty synthetic results. When the tool fails, you can either retry with smaller prompts or do the work directly. The fix isn't to keep retrying — it's to design prompts that fit the tool's reliability envelope.

4. **TypeScript types don't enforce at runtime.** The Glyph FileTree crash was a perfect example: the TS type allowed `"rewritten"` but `FILE_CHANGE["rewritten"]` was `undefined`. Either the runtime check or the type needs to be stricter — usually both.

5. **Glyphs beat long planning messages.** A 12-section visual artifact with layout diagrams, decision tables, and acceptance criteria is easier to review than 12 paragraphs of prose. The user reviews faster, catches more issues, and the artifact persists as documentation.

</Callout>
