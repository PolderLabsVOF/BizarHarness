**Date:** 2026-06-18

## TL;DR

Closes the last open item from the [2026-06-18 startup hang postmortem](../postmortems/2026-06-18-plugin-state-deadlock.md) — Layer 1 was documented as "fixed" but never actually landed in the code. This release applies the fix and adds a regression test.

## What's fixed

### Plugin: 1-second startup timeout on `client.session.list()`

**Symptom (would have manifested on broken/slow session stores):**
- OpenCode renders a blank screen on launch
- The plugin's `init()` never resolves
- The UI pipeline stalls indefinitely

**Root cause:** The postmortem documented a 6-layer fix for a startup hang, but Layer 1 (a 1-second timeout on `client.session.list()`) was only described in prose — the actual code change never landed. Anyone who hit a slow session store after v0.5.0 would still have seen the blank-screen bug.

**Fix:** `plugins/bizar/index.ts:537-575` now races `client.session.list()` against a 1-second timeout via a small `withTimeout(promise, ms, label)` helper. On timeout, the function returns an empty set (the age-based cleanup branch still runs, per spec §4.6). A no-op `.catch(() => undefined)` is attached to the original promise to prevent late-rejection crashes after the race winner is discarded.

**Regression test:** `plugins/bizar/tests/init-helpers.test.ts` — 11 new tests covering:
- `withTimeout` directly (4 tests): resolves in time, rejects on timeout with labeled error, propagates underlying rejection, clears timer on success
- `readValidSessionIds` integration (7 tests): normal paths, missing client, hanging client (the actual bug — verifies the function returns within 1.5s when `list()` never resolves), late rejection does not crash the process

The hanging-client test passes in 1002ms — the timeout fires exactly as designed.

## Upgrade path

```bash
cd BizarHarness
git pull
./install.sh
# restart opencode
```

The install script copies the new plugin source to `~/.config/opencode/plugins/bizar/`. The fix is active on the next opencode startup.
