# Release Notes — `@polderlabs/bizar@2.3.0`

**Date:** 2026-06-18
**Tag:** `v2.3.0` (CLI)
**Companion plugin release:** `@polderlabs/bizar-plugin@0.5.4`

## TL;DR

**The CLI is now `bizar`.** The old `bizarharness` command is gone. New `bizar update` subcommand updates the cline CLI, `@polderlabs/bizar`, and `@polderlabs/bizar-plugin` in one go. All in-repo references are updated.

The old `@polderlabs/bizarharness` package is **deprecated** — install the new one with `npm install -g @polderlabs/bizar` and use the `bizar` command.

## What's in 2.3.0

### Renamed: `bizarharness` → `bizar`

- The CLI bin in `package.json` is now `bizar` (was `bizarharness`).
- All help text, error messages, and examples use the new name.
- The npm package is renamed to `@polderlabs/bizar` (was `@polderlabs/bizarharness`).

### New: `bizar update` subcommand

Update the cline CLI, the `@polderlabs/bizar` package, and/or the `@polderlabs/bizar-plugin` package in one command. The default mode prompts for each component; `--all` and explicit subcommands skip prompts.

| Form | What it does |
|---|---|
| `bizar update` | Interactive: prompt for each component |
| `bizar update --all` | Update everything non-interactively (CI-friendly) |
| `bizar update cline` | Update only the cline CLI |
| `bizar update bizar` | Update only `@polderlabs/bizar` |
| `bizar update plugin` | Update only `@polderlabs/bizar-plugin` |
| `bizar update --help` | Show the help text |

Each update first reports installed vs. latest version, then runs the appropriate installer:
- `cline upgrade` (with `npm install -g cline@latest` as fallback)
- `npm install -g @polderlabs/bizar@latest`
- `npm install -g @polderlabs/bizar-plugin@latest`

After any package update, `bizar update` re-runs the install script (`install.sh`) so the locally deployed plugin source matches the just-installed npm version. This fixes the BUGS.md "version skew" trap — pre-2.3.0, the installed plugin could be one version behind the registry.

## What's not in 2.3.0

- No breaking changes for users who already used `bizarharness`. The new command is `bizar`; update your shell alias or scripts accordingly.
- The brand name "BizarHarness" is preserved in titles, project metadata, and the GitHub repo name.
- The `.bizar/` project directory and `plugins/bizar/` plugin directory names are unchanged.

## Upgrade from `bizarharness`

If you're already on the old name:

```bash
# 1. Install the new package
npm install -g @polderlabs/bizar

# 2. Verify
bizar --help

# 3. (One-time) Re-run the install script from the BizarHarness source
#    to update the deployed plugin from bizarharness-plugin to bizar-plugin
cd /path/to/BizarHarness
./install.sh

# 4. (Optional) Uninstall the old package
npm uninstall -g @polderlabs/bizarharness
npm uninstall -g @polderlabs/bizarharness-plugin
```

The old `@polderlabs/bizarharness` and `@polderlabs/bizarharness-plugin` packages are deprecated on npm — installs will print a deprecation notice pointing to the new names.
