# Release Notes — `@polderlabs/bizar@3.24.0`

**Date:** 2026-06-29
**Tag:** `v3.24.0`
**Companion dashboard release:** `bizar-dash` v3.24.0

## TL;DR

**The Hindsight MCP is gone. Bizar Memory Service replaces it.** Memory is now local-first: notes are Obsidian-compatible Markdown files with strict YAML frontmatter, stored in a Git-managed vault, and synced via standard `git pull / commit / push`. No external API keys. No hosted service. No network calls between you and your memory.

Phase 1 ships the full Markdown + Git stack — the `bizar memory` CLI, the `/api/memory/*` dashboard routes, schema validation, secret scanning, and back-compat with the legacy `/api/obsidian/*` surface. Phase 2 will wire the existing `mods-examples/lightrag/` server in as a derived retrieval index, rebuildable from Markdown on demand.

## The three-layer model

```
   ┌─────────────────────────────────────────────┐
   │ Layer 1: Markdown is truth                  │  ← canonical store
   │   .obsidian/  or  ~/.local/share/bizar/…    │     (frontmatter + body)
   ├─────────────────────────────────────────────┤
   │ Layer 2: Git is collaboration               │  ← sync + version control
   │   bizar memory pull / commit / push / sync  │     (branches, conflicts)
   ├─────────────────────────────────────────────┤
   │ Layer 3: LightRAG is derived index (P2)     │  ← semantic retrieval
   │   bizar memory reindex                       │     (stub in Phase 1)
   └─────────────────────────────────────────────┘
```

Markdown is canonical. Reindexing rebuilds the LightRAG index from Markdown at any time — never the other way around. You can rip out the LightRAG layer and the system keeps working: it's a cache, not a source of truth.

## Two modes

| Mode | Vault location | Default? |
|---|---|---|
| `local-only` | `<project>/.obsidian/` | **Yes** — best for single-project use |
| `managed` | `~/.local/share/bizar/memory/<repoName>/` | Opt-in — best for cross-project sharing |

Pick `managed` at `bizar init` time, or run `bizar memory link <repo>` on any existing project. The `managed` repo splits into three namespaces:

| Namespace | Purpose |
|---|---|
| `projects/<projectId>/` | Per-project memory — conventions, ADRs, bugs, commands |
| `global/bizar/` | Cross-project knowledge — agent patterns, Bizar internals |
| `users/<userId>/` | Personal scratch — user preferences, todos, draft thoughts |

## What's in 3.24.0

### New CLI: `bizar memory <sub>`

Eleven subcommands cover the full lifecycle of a memory note:

| Subcommand | Purpose | Example |
|---|---|---|
| `init` | Create `.bizar/memory.json` and the per-project vault | `bizar memory init --memory-mode local-only` |
| `status` | Show mode, link target, dirty files, last sync | `bizar memory status` |
| `link` | Bind the project to a managed memory repo | `bizar memory link ~/.local/share/bizar/memory/work/` |
| `unlink` | Detach from managed mode (vault stays on disk) | `bizar memory unlink` |
| `pull` | `git pull` the linked memory repo | `bizar memory pull` |
| `commit` | Stage dirty notes + run secret scan + `git commit` | `bizar memory commit -m "add auth ADR"` |
| `push` | `git push` the linked memory repo | `bizar memory push` |
| `sync` | pull → reindex → commit → push (the common path) | `bizar memory sync` |
| `reindex` | Rebuild the derived LightRAG index (Phase 2 stub) | `bizar memory reindex` |
| `conflicts` | List notes with merge conflicts awaiting resolution | `bizar memory conflicts` |
| `doctor` | Run schema + secrets + Git health checks | `bizar memory doctor` |

### New dashboard routes: `/api/memory/*`

Eighteen REST endpoints for programmatic access. Legacy `/api/obsidian/*` routes are preserved with back-compat response shapes so existing integrations keep working.

The full route list (18): `/status`, `/notes` (GET/POST), `/notes/:id` (GET/PUT/DELETE), `/search`, `/schema/validate`, `/secrets/scan`, `/git/pull`, `/git/commit`, `/git/push`, `/git/sync`, `/git/conflicts`, `/reindex`, `/link`, `/unlink`, `/doctor`.

### Schema and secrets

Required frontmatter: 8 fields (`memory_id`, `type`, `project_id`, `status`, `confidence`, `created`, `updated`, `tags`). Recognized: 11 memory types, 6 statuses (`active`, `superseded`, `stale`, `conflict`, `draft`, `archived`), 3 confidences (`verified`, `inferred`, `speculative`).

Every note passing through `bizar memory sync` (or `commit`) is scanned against 12 secret patterns defined in `bizar-dash/src/server/memory-secrets.mjs`. HIGH-severity matches (PEM private keys, AWS access keys, GitHub PATs, Stripe live keys, bearer tokens) **block the commit**. MEDIUM-severity matches (test API keys, absolute paths, private IPs) **warn but allow**.

## Migration from Hindsight

The Hindsight MCP is disabled by default as of 3.24.0. If you're upgrading from a previous version:

1. **Pull the new release** — `npm update -g @polderlabs/bizar` or `git pull && ./install.sh` from source.
2. **Re-initialize project memory** — `bizar init` now prompts for memory mode and writes `.bizar/memory.json`. The default is `local-only`.
3. **Migrate existing notes (optional)** — Hindsight notes are not auto-migrated. Export from the Hindsight dashboard and import as Markdown files into `<project>/.obsidian/`. The Memory Service schema requires the 8-field frontmatter; you may need to massage the imports with `bizar memory schema/validate` (or `POST /api/memory/schema/validate`).
4. **Drop the Hindsight env var** — `HINDSIGHT_API_KEY` is no longer read. The `bizar memory` command family is the replacement.

## LightRAG status

`bizar memory reindex` is a STUB for Phase 1. It returns a "not yet implemented" notice and exits cleanly. Phase 2 will integrate the existing `mods-examples/lightrag/` server as the derived retrieval index, rebuildable from Markdown at any time. Until then, retrieval is grep and full-text search over Markdown — fast, local, and dependency-free.

## Upgrade from `v3.23.x` and earlier

```bash
# npm path
npm update -g @polderlabs/bizar

# source path
cd BizarHarness
git pull
./install.sh

# Re-initialize project memory (in each project you want to keep memory for)
cd ~/my-project
bizar memory init
```

The installer is idempotent. If you opt into `managed` mode, the first `bizar memory sync` will create the shared repo and push the initial commit.
